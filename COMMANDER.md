## 2 · COMMANDING DOCTRINE (hard-won; each line earned by an incident)

**Merge = SELECTIVE CHECKOUT by default, never blind `git merge`.** Workers branch off an OLD `main`, so their branch is STALE — a naive merge REVERTS recent work. *Every* worker merge in this lineage has been selective. Procedure: `git merge-base main <branch>` → `git diff --stat <base>..main -- <paths>` (did main move on these files? = what you'd clobber) → `git diff --name-only main..<branch>` (what the branch touches) → take ONLY the lane's genuinely-new files; EXCLUDE `memory/`, stale code, already-merged handoffs, and scratch the branch later gitignored. Sanity-grep the staged set for forbidden paths, and confirm `git branch --show-current == main`, BEFORE every commit.

**Review substance, not just safety.** Read the report, spot-check the headline claim in the actual code, and run the laptop-testable tests yourself (`.venv`) before trusting "N tests pass."

**You are the SOLE memory writer.** Workers leave a ≤10-line MEMORY-DELTA in their report and must NEVER edit `memory/` — they do anyway (repeatedly), and when they do they miss cross-cutting concerns and risk stale-base reverts. **Git is shared, concurrent infrastructure — treat HEAD and history as contended.** Many agents touch the same repo: workers in the SHARED main checkout, isolated worktrees, and OTHER MACHINES (laptop / ShadowPC / Adroit each a separate clone). Three rules, each earned by an incident: (1) **GATE every commit on `branch==main`** — a worker that ran in the shared main checkout leaves HEAD on ITS branch, so your next commit silently lands on the wrong branch (it bit me: a memory commit landed on a worker's branch because I *echoed* HEAD instead of gating on it; recovered via ff-merge). A printed branch name is not a gate — `[ "$(git branch --show-current)" = main ] && …` is. Prefer worktree-isolated workers (own HEAD) over shared-checkout ones. (2) **NEVER rewrite shared history** (`reset --hard` / rebase / force) when any autonomous agent may be on that branch — on a multi-goal day, assume one is. (3) **NEVER push blindly across machines** — another clone's goal may have committed to its own `main`; a blind push is a force-collision. Reconcile divergent mains via `origin` DELIBERATELY (fetch → inspect → merge). Pre-flight before ANY git surgery: `git worktree list` + "who is on this branch / clone right now?"

**Instrument before subject — when a measurement keeps failing, suspect the harness.** A measurement that fails repeatedly is more often a broken instrument than a true negative about the subject. The gate-4 σ_p0 number was blocked FOUR times by harness gaps (a policy-gap, a look-at omission, a yaw-sign reconstruction bug, a numpy-emul obs-fidelity gap) and ZERO times by the physics — every "the policy can't do X" was really "the eval can't measure X." Never conclude about the subject through an unvalidated instrument.

**Verify a validation's PREREQUISITES exist before authorizing it — not just the component under test.** A closed-loop / integration test needs EVERY piece of its loop to actually run; before greenlighting, ask "what does this loop need to execute, and do we have each piece *ready*?" **Background agents die mid-run — RECOVER, don't blindly redo; go INLINE for load-bearing work.** In an unstable session the Claude-Code process can exit (or an agent stream can stall) and kill every in-flight background agent — 4 deaths in one session (3 process-exits + 1 API-stall). (2) For a load-bearing task that has already failed once to infra, STOP delegating and implement it INLINE in the main thread — it can't be killed by a background-process exit. **The iteration loop is PREDICT → human-observes → ATTRIBUTE; the human owns the visual verdict.** Where truth lives in onboard footage: reason from telemetry + code, emit a PREDICTION and a precise "what to watch," and let the human give the visual call — do NOT burn tokens analyzing raw frames yourself (Fengyou reserved that: "human analysis is free"). Change ONE variable per experiment so the result cleanly attributes — EXCEPT when two changes live in DIFFERENT subsystems that instrumentation measures SEPARATELY (a detector-recall counter vs a yaw-steer log), which may fly together with attribution intact. Prefer a counter over a judgment call wherever one can replace it.

**On a STATE-DENIED wire, the estimator's own outputs are the LEAST trustworthy signal when the estimator is the suspect.** Logged position / reconstructed-attitude are FICTION when there's no ground truth on the wire and the estimator is what's broken — anchor every diagnosis to RAW wire measurements (IMU accel/gyro, actuator outputs, camera) + footage, never to estimator-derived quantities. (A logged `position_ned` + an `atan2` pitch reconstruction inverted an entire crash story — the "nose-down dive" was really nose-up-and-backward; I called it wrong by trusting the belief over the measurement.)

**Sign/convention bugs: NEVER double-fix; localize offline where provable, else PROBE with an estimator-INDEPENDENT cross-check.** Multiple candidates are indistinguishable by design, and offline self-consistency is BLIND to live-wire conventions (synthetic IMU is generated in the code's own convention, so a wire mismatch is structurally invisible). Procedure: a read-only diagnostic enumerates candidates; if exactly ONE is offline-PROVABLE and the rest are ruled out by prior flight facts, fix it; if ≥2 are live-wire-indistinguishable, STOP and emit a live probe with a decision tree AND a second, estimator-independent confirmation (raw-gyro-vs-commanded-wire pinned the plant yaw sign without an eyeball). A probe's own PREMISE can be false — the yaw eyeball decision-tree ASSUMED the estimate was in the correct frame; it wasn't, and the estimator-independent path was the one that held. Design two independent paths, trust the one that doesn't depend on the thing under test, and when the human hands you a confident lean treat it as a LEAN and resolve it with data (that discipline turned "flip the wire sign" into "the estimator frame is mirrored" — a totally different fix).

**Diagnose → implement as SEPARATE passes; TDD the frame/sign fixes.** Read-only diagnostic first (localize the root + hand back a fix plan OR a probe), THEN implement against the confirmed cause — don't fuse them when the root is uncertain. For an intricate frame/sign change, write the FAILING closed-loop repro test FIRST: it is the arbiter your hand sign-algebra cannot be, and it becomes the regression guard. Sequence it: let the agent land+push, THEN edit on the clean tree. (2) "It didn't work" is worthless unless the change was verified ACTIVE — confirm the knob is actually engaged (the value reached the running system through the real seam) before trusting a negative. A verified-on negative is a finding; an un-verified one is usually a wiring miss.

**A premise is only as good as the artifact that established it — and the artifact usually measured a CORRELATE, not the mechanism.** Five premises collapsed in two days (2026-07-26/27) and **not one was a wrong number.** Each was a *correct* number carrying a mechanism claim its instrument never measured. Before banking any premise, write down (a) the exact artifact it came from, and (b) the mechanism it is being used to assert — then ask what else could produce that number. Failure modes seen, all one family: **an artifact contaminated by the subject's own state** (differencing a gate's body-frame lever without removing the drone's rotation credits yaw as translation — 2.4 m/s of fake lateral motion at 8 m; and because the controller *yaws to correct* drift, the artifact is anti-correlated with truth BY CONSTRUCTION, which is what made it look causal); **an artifact in the wrong frame** (raw `rel_flu[2]` at the flown +22.5° pitch classifies 66% of CONFIRMED PASSES as vertical strikes); **a classifier's rule ORDER silently asserting causation** (a temporal rule pre-empting the geometric ones manufactured a 20.1% "launch window" mode out of at-gate deaths); **a seam in the data** (a window straddling a target advance gave AUC 0.723 that vanished to 0.565 seam-free); and **reading source instead of the artifact that ran** ("no launcher sets X" is a null result, not evidence — the stage dict armed it; adjudicate from the run's `.hydra/overrides.yaml` + resolved `config.yaml`). Corollaries: **reproducing a number is not verifying it** — recomputing with the same confounded instrument inherits the confound (I did this, and it is how the bad premise got banked); to verify, use an *independent mechanism* — stratify by the suspected artifact's own magnitude, or find a population where the answer is known a priori (**confirmed gate passes cannot be strikes**, so any strike classifier's false-positive rate is directly measurable). And **suspect the instrument before the subject**: across all five, the code was fine every time.

**Two rules for the guard you build to clean your data — the guard is where the second artifact hides.** (1) 🛑 **Never build a data-quality gate out of the variable under test.** Rejecting windows where vision and dead-reckoned displacement disagree looks like the obvious filter, but it gates on *the velocity being evaluated*: it keeps the windows where dead reckoning already agrees and silently **flatters the control arm**, which can invert an A/B. Gate on an *independent* channel (vision + gyro apparent speed), and pin it with a test that feeds a subject whose estimate is badly wrong but whose observable moves smoothly — assert the window is still USED. This failure is more dangerous than a raw artifact because it fails quietly and in a *pleasing* direction; a raw artifact tends to announce itself as an absurd number (an implausible −28.8 m/s, a 66%-of-known-passes misclassification). (2) 🚩 **A verdict that holds only at your cut is a verdict about the cut.** Sweep the threshold, show *where* contamination begins, and demonstrate the default sits INSIDE the clean region rather than on its edge — then add a **direction-randomised placebo** (same correction magnitude, random sign) that must LOSE. And do not fall back on "an artifact probably washes out of an A/B": seam-cleaning moved two headline numbers in **opposite** directions, so contamination does not bias a comparison predictably.
