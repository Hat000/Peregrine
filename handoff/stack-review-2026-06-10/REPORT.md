# STACK-REVIEW-VQ2 — adversarial architecture review (2026-06-10, fable background agent, report-only)

Commissioned by COMMANDER-2 at user request ("is YOLO-pose corners the best we can field? Depth Anything 3? VSLAM?").
Grounded in memory + measured handoffs; 2025–26 landscape swept; settled-decision ledger honored.

**Headline:** the stack is architecturally sound and unusually well-measured; no component needs replacement. The rank-relevant exposure is not in any single component but in three *meta* gaps: (1) the policy is trained on exactly ONE track while VQ2 is an unseen course run unattended by the organizers; (2) there is no time-optimal reference, so we don't know how big the prize is (35.3 s vs what bound?); (3) the vision-only contingency (VQ2 case C) has unbuilt, cheap, champion-validated pieces (latency rewind, range-anisotropic R, the yaw-bias calibration solve). The 2025 A2RL champion stack ([MonoRace, TU Delft/MAVLab](https://arxiv.org/abs/2601.15222)) validates our architecture class (monocular gate perception + known-geometry calibration refinement + learned controller) — nothing they fielded that applies to a setpoint-over-MAVLink sim is missing from our plan except the offline calibration solve we already have queued.

**Cross-cutting — latency budget (from code, not run):** `navigator.py` has zero latency instrumentation; `detector.py` runs `model.predict` at default imgsz/device; the KF applies vision fixes at "now" (documented TODO, never built); ShadowPC's torch install is **CPU-only** — YOLO11s at 640 on CPU is plausibly 30–80 ms, never measured in-loop (vision flew OFF in VQ1). For vision-only VQ2 this chain (decode→detect→PnP→KF) is a first-order unknown. **100 TOPS:** governs the *physical* round; whether the virtual eval gives our stack a GPU at all is unknown — do NOT size models to 100 TOPS for VQ2 until the submission interface spec lands.

## (b) Top upgrade candidates, ranked (rank-impact ÷ cost, 6-week window)

1. **Procedural track randomization in the RL env + VQ1-course-as-held-out-eval.** Impact: potentially binary (a one-track policy on an unseen VQ2 track in an unattended eval may score zero); cost: low (extend `rl/peregrine_course.py` to sample gate layouts within spec geometry; obs already track-agnostic). *First experiment:* generate 1k random 6-gate courses (spec-plausible spacing/descent), retrain the S1.3 recipe on them, report success on the held-out VQ1 course vs the single-track baseline — if the randomized policy matches single-track performance on VQ1, ship it as the default training mode. Fold into the already-planned env-coherence redesign session.
2. **Offline time-optimal reference line on the corrected twin (TOGT-Planner, CPC as bound).** Impact: high — quantifies remaining headroom (35.3 s → bound), supplies the progress-reward reference and the S2 decomposed line; cost: ~3–5 days (Run-TOGT-Planner on WSL/Adroit; feed the new ~11 rad/s authority + measured thrust ceiling). *First experiment:* plan the VQ1 course, replay the line through the twin with the CTBR tracker, report twin lap time vs 35.3 s.
3. **Vision-only readiness package** (gated on the organizer answer, but pieces are useful regardless): delayed-fix rewind ring buffer; range-anisotropic R (depth-axis ∝ r²); offline yaw-bias calibration solve over a recording (MonoRace-validated practice); measure in-loop perception latency on ShadowPC (and get torch-GPU or ONNX there). Impact: high in case C, moderate in A/B; cost: ~1 week total, mostly independent small pieces. *First experiment:* re-run `characterize_perception` with the anisotropic R + calibrated yaw, count residual leaks (target: 2→0) and good-fix yield.
4. **Learned residual dynamics on the twin** (Learning-on-the-Fly pattern). Impact: medium — closes the ~25% latency under-model + unmeasured racing-airspeed aero, the last transfer-gap term; cost: medium, and must pass the parity-gate discipline (residual = additive module, off by default). *First experiment:* fit residual on the canonical course recording, report one-step prediction RMSE vs analytic twin on a held-out run; only then consider training with it.
5. **YOLO26-m-pose at the VQ2 photoreal detector retrain** (not before). Impact: low-medium (RLE keypoint σ → weighted PnP; NMS-free latency; insurance on photoreal clutter); cost: near-zero marginal — same pipeline, one model-name change, A/B on the fixed eval set against v2. Never fine-tune on clean VQ1 frames (doctrine stands).

## (c) Examined and rejected (do not re-litigate without new evidence)

- **Depth Anything 3 for gate depth** — verdict re-verified and HOLDS: [DA3](https://arxiv.org/abs/2511.10647) (Nov 2025) is real SOTA, but metric mono-depth relative error at 25–38 m from a 640×360 frame is ≥ the PnP depth noise it would replace, and known-size+intrinsics PnP is the geometrically correct tool (our own clean-subset measurement: depth bias ~0). DA3 remains valid for the *offline obstacle* flywheel only.
- **RT-DETR / D-FINE / RF-DETR class** — still bbox-first; no 4-keypoint pose path that beats ultralytics-pose for a single-class 640×360 problem. Prior rejection stands; YOLO26 is the in-family upgrade.
- **Foundation-model distillation for gate corners** — solves an open-vocabulary problem we don't have; the synthetic generator + DR already owns this domain.
- **Learned 6DoF gate pose (PVNet-class)** — stays parked; the measured failure modes (scale-error boxes, yaw calibration) are not things dense voting fixes.
- **Tightly-coupled VIO (OpenVINS/VINS-Fusion)** — stays parked; attitude is given; case-C bounded gate-SLAM covers the rest.
- **GTSAM as the online estimator / sliding-window smoother in-loop** — linear KF + rewind buffer is near-optimal for a linear position problem; GTSAM is offline-mapper-only.
- **Isaac Lab re-promotion** — no 2026 development changes the calculus; DiffAero + injected plant is proven at 88.9K steps/s with machine-epsilon parity.
- **Crazyflow switch** — JAX throughput we don't need; would re-pay the entire plant-injection + parity cost.
- **MPPI reference-free racing in-loop** ([2509.14726](https://arxiv.org/html/2509.14726)) — elegant, but needs GPU dynamics rollouts inside the live control loop on unknown eval hardware; our committed RL policy is the same objective baked offline. Revisit only if RL transfer fails twice.
- **G&CNets / direct motor commands** (the MonoRace control layer) — interface-impossible: we command CTBR into a black-box stabilizer; take their calibration practice, not their actuator level.
- **Pixel-to-control RL** — re-affirmed; even the 2025–26 "vision-based" racing papers ([2512.09571](https://arxiv.org/abs/2512.09571)) feed *depth*, not RGB, and still need privileged→visual curricula.
- **Iterative-learning MPC** ([2508.01103](https://arxiv.org/pdf/2508.01103)) — concept already owned by the determinism + offline-line-iteration flywheel; the library adds nothing.
- **v3-style hard-tail oversampling, K=2.0 cov inflation, tilt-threshold termination, ωₙ/ζ-envelope DR** — all already disproven with data; listed here so the ledger is in one place.

## (d) Measured-data gaps this review exposed

1. **In-loop perception latency** — no number exists anywhere for decode→detect→PnP→KF on race-representative hardware (ShadowPC torch is CPU-only). Blocks honest Stage-2 twin latency injection.
2. **Submission-eval persistence** — can the stack carry state (map, tuned line) *between attempts* in the organizers' controlled eval? This decides whether track-randomized generalization is mandatory (no persistence) or insurance (persistence). Add to the organizer email alongside the pose-stream question.
3. **Time-optimal bound for the VQ1 course** on the corrected plant — without it, "where rank is won" has no denominator. Upgrade #2 produces it.
4. **Aero at racing airspeed** — sweep caveat stands (all probes near hover); one cheap high-speed pass-through probe would bound it; the DR band covers meanwhile.
5. **Eval-hardware compute envelope for virtual quals** — unknown whether our stack gets a GPU; gates detector sizing and any in-loop learned component.
6. **VQ2 photoreal frames** — zero exist; the detector's true VQ2 axis (appearance) is unmeasured and unmeasurable until organizers release anything — which is exactly why the DR doctrine must not be diluted.
