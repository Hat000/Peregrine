# 11 — Fresh-Eyes Audit (2026-07-09)

**What this is.** Fengyou ordered a 15-agent adversarial audit of the whole VQ2-ego single-gate
campaign and this dossier on 2026-07-09 (same day as most of Era 6). Five readers each re-derived one
slice from primary sources (code, git, the Adroit connector's `command_history.log`) with NO access to
this dossier's own conclusions; a critic then tried to refute each of 8 headline claims from the
readers' findings, three ways per claim. Full source: `handoff/audit-ego-inc9-2026-07-09/verdicts.md`
(verdicts + refutation attempts) and `critic.md` (confounds, cheap experiments, contradictions, the
recommended next run). **5 of 8 claims were REVISED or REFUTED.** This file condenses the verdicts;
it does **not** replace them — read `verdicts.md` for the full evidence chains and line citations.
Per dossier convention, every file below carries a 🛑 banner at the affected passage; **nothing was
deleted or rewritten in place.**

## C1 — Perception-limited: CONFIRMED, mechanism narrowed (0.80)

The headline (`vglpns0` perfect-estimator ablation: thread 0.20→0.63, xoff 0.88→0.32 m) is real —
raw watcher artifacts locally confirm the dose-dependent divergence from bit-identical step-30 starts,
and it is immune to the C2 anneal-inert bug (noise is set at env-construction, not the broken hook).
**Two corrections:** (1) rename to **"estimator-corruption-limited"**, not "perception-noise-limited" —
`ego_noise_scale=0` also zeroes 10% misses, teleports, the ≤0.19 m per-episode bias, and IMU blind-gap
drift; the ablation does not isolate in-frame σ specifically, so a fix targeting only sigma may recover
less than 0.88→0.32 suggests. (2) the DET_EVAL 0.641 figure and the exact launch EXTRA are Adroit-only,
unverified locally; n=1 seed.

## C2 — Anneal-inert bug: CONFIRMED (0.93)

Verified end-to-end: DiffAero vendors its own `RecordEpisodeStatistics` whose `__getattr__` explicitly
raises on underscore names, so `hasattr(env,'_egorw')` was deterministically False. `vglpan`'s own
Adroit stdout (captured verbatim, `command_history.log:76596-76598`) contains exactly one
`[cross-zero-anneal] requested but env._egorw missing -- SKIPPED` line and zero update-logging lines —
**`vglpan` trained the whole run at fixed `cross_zero=4.0`, never the 4→0.75 anneal.** The `vns01`/`vns31`
bit-identical DET_EVAL pair (0.0051 to 4 decimals, both logs showing the noise-scale hook SKIPPED) is
independent proof of the same mechanism. Fix `4f91bd8` is correct by code inspection (walks the real
`.env` instance-dict chain). **Residual hole: no post-fix `[...anneal] ON` banner has been observed
locally for `vcza2`/`vnsb`** — the fix's runtime efficacy is code-verified, not yet observation-verified.

## C3 — `r_perc` rejection: REFUTED (0.78)

The implementation is not a strawman (form/weight match Geles). But the rejection run (`vperc05`/`vperc15`,
warm from `vglpan`) silently carried a **hidden discrete `cross_zero` 4.0→0.75 jump** on top of `r_perc`
(the `vperc` stage statically sets zero=0.75 "champion settings", but real-`vglpan` trained at 4.0) —
exactly the discontinuity class the dossier's own L1 says detonates warm-starts. The **no-`r_perc`
control collapsed identically** (`vns01`/`vns31`, same hidden jump, zero reward change, DET 0.0051), so
the observed collapse cannot be attributed to `r_perc` over the confound. The field trains `r_perc` from
scratch where crossing is positive-EV; here it was warm-added where a 0.88 m crossing is already
near-neutral/negative-EV under the reward's actual (unannealed) config. **Verdict: move `r_perc` from
REJECTED back to UNTESTED-CLEANLY** — retest warm from `vglp4` at its native zero=4.0, single lever,
record the failure mode (oob split) separately.

## C4 — Speed lever: REFUTED as a compound claim (0.80)

The **narrow** result stands: `rw_vmax_mps` (39→5→3) is a reward-credit clip on progress, not a
dynamics constraint (zero hits grepping for velocity limits in the env/dynamics code); lowering it made
centring monotonically *worse* (0.88→1.57→3.29 m), so the cap is not a useful knob. But the **compound
claim "therefore a slower crossing is not a path to tighter centring" is refuted**: no run ever measured
the actual crossing speed (the "~8 m/s" figure is a back-of-envelope estimate, not telemetry), and the
dossier's own text already disclaims this ("refutes the lever, not the physics"). `metrics/mean_speed`
is logged but never pulled. **A speed-at-plane penalty remains genuinely untried**, and is specifically
relevant to `vglpns0`'s residual 36% failures, which are near-centred *collisions* — exactly the mode a
slower, more correctable crossing could address.

## C5 — 36% control residual under perfect perception: REFUTED (0.80)

`vglpns0` also trained at fixed `cross_zero=4.0` (same inert-anneal bug as `vglpan`; job-id ordering and
the fix commit timestamp confirm it predates `4f91bd8`). At zero=4.0, a 0.32 m crossing already earns
99.4% of the parabola max, and with `parabola_crossing` on, a **0.8 m frame-clip earns +19.2 of 20** —
the run had almost no reward gradient distinguishing a thread from a clip. **No run exists that pairs
`noise_scale=0` with a working cross-zero anneal** (the two post-fix single-lever runs, `vcza2`/`vnsb`,
both died at step ~570 with no result). So the 36% residual may be reward-limited, control-limited, or
both — current data cannot distinguish. **Demoted from conclusion to hypothesis.** The missing
calibration run is `vczns0`: `noise_scale=0` + the real (post-fix) 4→0.75 anneal, warm from `vglp4`,
with a mandatory `[cross-zero-anneal] ON` log check.

## C6 — `_run_det_eval` faithful: CONFIRMED (0.85)

Confirmed by code inspection (`self.env` is literally the live training instance — same DR, same
estimator noise, same termination), by a raw local capture of `vglpanEV`'s `DET_EVAL` line matching the
committed print format, by verifying the frozen-actor trick (`critic_warmup_updates=100` > 5 updates,
grads zeroed, plain Adam ⇒ mean untouched), and by statistical power (n_ep≈19967, SE≈0.3pp) on the
det≥stoch direction. **Three caveats to carry forward, not full refutations:** (1) "thread" is a
point-mass geometric criterion (interpolated crossing < aperture − body radius), not a
collision-simulated pass — fine for relative progress, but the 90% target must ultimately be validated
in the real VQ2 sim; (2) any stage using `gate_inner_opening_m` inflates "thread" — compare
`cross_offset_m` instead; (3) the offline harness (`ego_render_rollout.py`) is still broken with unknown
root cause — do not resurrect it. **New finding, not previously flagged:** DET_EVAL's default 300-step
(10 s) horizon vs `max_time=40 s` censors slow-terminating episodes out of the sample; magnitude
unmeasured (see 00-CORRECTION for the follow-up note).

## C7 — Noise/bias contract provenance: REFUTED (0.87)

The estimator's sigma floors (lat 0.1045 / vert 0.2816 / depth 0.8524) are **VQ1-era**, fit 2026-06-14
to Track-3 orange-gate shadow recordings (6 flights, 125 clean fixes, 10–26 m band) — 10+ days before
the VQ2 spec existed, and never recalibrated for VQ2's dark warehouse / glowing red gates / 5–20 m
spacing. **`miss_prob=0.10` and `teleport_prob=0.002` have zero measurement provenance anywhere in the
repo** (first appear in commit `668347f` with bare comments) and `miss=0.10` (90% accept) directly
**contradicts** the only availability measurement that exists (Track-3 measured P(accept|in-image)≈0.089,
i.e. ~91% *miss*). The vertical sigma (0.2816) is contested by the project's own later VQ1 analysis
(boresight-closure 2026-06-15): the true anisotropic sigma is lat 0.19 / vert 0.10, and 0.28 is a
**pooling artifact** that conflates scatter with a −0.215 m one-signed (calibratable) sighting bias. The
`[b,0,b]` bias model also over-injects lateral bias ~5× vs measurement and randomizes the sign of what
was measured one-signed (see the bias-bug note below). **Consequence: `vglpns0`'s 0.63/0.32 m stands
only relative to this contract, not to reality** — real VQ2 availability is plausibly far worse
(GPU-contention detect 32–234 ms swings, detector barely fed until A19), so perception's true share of
the failure is likely *underestimated*, not overestimated, by this ablation.

## C8 — Warm-start collapse law (L1, "6× observed"): REFUTED, weaker law survives (0.82)

Re-checked all 6 claimed collapses against the actual stage configs: **1 of 6 was not a warm-start at
all** (`vgk10a`, fresh), **2 carried the same hidden discrete 4.0→0.75 zero jump** as the `r_perc` runs
(`vglpsub`, `vglpc40`), leaving **2 clean single-lever collapses** (`vgap8`, `vglp3`). Counter-examples
found: **4 discrete-reward-change survivals** (`vgctrw`, `vglp4`, `vglp3c`, `vglpsl5`/`vglpsl3`) plus one
massive obs-change survival (`vglpns0`) — and the *same* discrete change (zero 3→4) survives from one
base (`vglp3c`, direct-from-champion) and detonates from another (`vglp3`, re-warm), so the law's "any"
quantifier fails, and its own carve-out ("warm-from-champion survives") also fails (`vgap8` was
warm-from-champion and collapsed). **Restated law:** *a discrete reward change that newly punishes the
policy's CURRENT operating point can detonate it, base-dependently* — 2 clean supporting observations,
not 6, all single-seed. Direct consequence: **"continuous anneal is safe" (L6) has zero clean positive
evidence** — the flagship anneal (`vglpan`) never actually ran one; `vcza2` is the first real test.

## Additional findings from the critic pass (`critic.md`)

**The `vglp05` accidental replicate — run-to-run variance is now demonstrated, not suspected.**
`command_history.log:74210-74217` recovers `vglp05`'s actual launch line: `EXTRA=++env.cross_zero_end=0.5`,
`UPD=4500`, same stage (`single_gate_varied_gvf_lpara_anneal`) as `vglpan`. Since the cross-zero anneal
hook was inert (C2), that `EXTRA` override was a **no-op** — `vglp05` ran **config-identical to `vglpan`**
except for +500 updates. Yet `vglpan` scored 0.20 thread / 0.88 m and `vglp05` scored 0.07 thread / 1.7 m
— **~2.8× thread / ~2× xoff spread between two runs of the (near-)identical config.** This single
accidental replicate is the only same-recipe pair in the whole campaign and it demonstrates that every
other n=1 comparison in [04] carries unquantified single-seed variance of at least this size — including,
uncomfortably, C1's headline `vglpns0` vs `vglpan` ratio (3.15×), which sits at the same order of
magnitude as pure noise. (What still favors C1: `vglpns0`'s xoff, 0.32 m, falls *below* the replicate
range, and its trajectory was a smooth monotone descent rather than an outlier jump — but confidence on
C1 should be read as lowered, not certain.)

**Obs blackout-masking cliff.** The actor observation builder zeroes a gate's `rel_pos` slot the moment
it becomes instantaneously non-detectable (`keep = valid & det & conf>0`,
`peregrine_racing_ego.py:~299-305`), **even when the estimator has a valid coasted/stale estimate with
residual confidence.** This directly contradicts `DESIGN.md §5.A`'s "brief ego-motion propagation
through gaps; mask past ~0.5–1 s stale" — the coast-through-gaps feature never reaches the policy. Since
the endgame approach is exactly where the gate leaves the FOV (+20° mount, close range), **the terminal
crossing is flown on zeroed observations even at `ego_noise_scale=0`** — meaning part of `vglpns0`'s
0.32 m residual is this masking cliff, not raw estimator noise or "control precision" at all. This is a
common-mode confound in the C1/C5 perception-vs-control split that no verdict fully isolates.

**Dead `_rel_var` state.** `BatchedEgoEstimator`'s per-axis variance state `_rel_var` is written
(`ego_estimator.py:273,346,477`) but **never read** by `estimate()` (`:535-565`) — there is no
covariance-driven gain anywhere in the emulator. Concretely, this means `latency_cov_inflate=1.5`
(advertised in `DESIGN.md §5.A` as "keeps" the FIX-B latency inflation) is a **silent no-op**: the
confidence signal reaching the policy is a pure staleness ramp, not a covariance-aware quality signal.

**The `[b,0,b]` bias bug.** The per-episode systematic bias is injected as `[lat, depth, vert] = [b, 0, b]`
— a single scalar shared by lateral and vertical, inherited from the inc8 emulator's `[b,b,0]` pattern
(`ego_estimator.py:367-373`). The actual VQ1 measurement (`sigma.json`) gives lateral bias **−0.034 m**
and vertical bias **+0.195 m (one-signed)** — i.e. the emulator **over-injects lateral bias ~5×**,
**fabricates a lat/vert correlation that doesn't exist**, and **randomizes the sign** of what was
measured as a consistently-positive (hence *calibratable*) vertical systematic, converting a fixable
offset into irreducible domain-randomization noise the policy must hedge against rather than compensate
for.

**Noise-contract provenance, summarized.** See C7 above for the full picture; net effect per the critic
pass is that the contract's errors do **not** all point the same direction — some terms are optimistic
vs. real VQ2 (90% miss-free vs. measured ~91% miss; zero content latency vs. measured 70–620 ms mixture)
and some are pessimistic vs. deploy (teleports pass through the K=1 blend un-gated, whereas the deployed
navigator's chi² gates would reject an 8 m teleport outright) — nobody has netted these, so whether
`vglpns0`'s delta over- or under-states real deployable headroom from a better estimator is **currently
undetermined**.

## What changes for the plan

The critic's ranked recommendation (full detail in `critic.md`, section (e)) is that the single
highest-information next training run is **`vczns0`**: warm from `vglp4`, the *real* (post-`4f91bd8`)
cross-zero anneal 4→0.75, `+env.ego_noise_scale=0`, with a mandatory `[cross-zero-anneal] ON` banner
check before trusting any result. It is the joint reward+perception **ceiling** measurement that C5
shows is currently missing, and every fork decision (vision-relay priority vs. reward rework vs.
obs/control change) depends on it. See `04-experiment-log.md`, `06-empirical-laws.md`,
`08-ideas-rejected-and-untried.md`, and `09-open-questions-for-the-oracle.md` for the passage-level
banners this audit propagated.
